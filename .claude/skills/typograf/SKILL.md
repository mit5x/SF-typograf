# Типографика русского текста

Правила по «§ 62. Экранная типографика» (Артемий Лебедев) и §§ 97, 104, 158 того же
руководства. Тот же набор правил реализован в плагине `sf-typograf/` этого репозитория —
если правило меняется здесь, оно должно меняться и в `sf-typograf/includes/class-sf-typograf-engine.php`.

Главный принцип § 62: **ни один текст не должен появиться на публике в исходном сыром виде**
и **везде используются настоящие знаки, а не их эмуляция другими знаками**.

## Порядок работы

1. **Уточнить область правки.** Если не сказано иначе, править только человекочитаемый
   текст: содержимое текстовых узлов HTML, значения строковых литералов, тексты в
   Markdown, значения текстовых полей в JSON/YAML. Ключи, имена, идентификаторы — не трогать.
2. **Выбрать режим вывода** — см. «Режимы вывода». Если режим не задан и по файлу его не
   видно, спросить один раз, потом применять ко всему файлу единообразно.
3. **Применить правила** в порядке разделов ниже: спецсимволы → пробелы → кавычки →
   тире → диапазоны → привязки. Порядок важен: например, `--` превращается в тире до
   того, как срабатывает правило неразрывного пробела перед тире.
4. **Отчитаться списком изменений.** Неразрывный пробел невидим, поэтому недостаточно
   показать diff — перечислить каждую правку словами:
   `«Коляныч - за пивом» → «Коляныч&nbsp;— за пивом» (дефис → тире, пробел → неразрывный)`.
5. **Проверить по чек-листу** в конце документа.

## Что не трогать никогда

Это важнее самих правил: сломанный код хуже плохой типографики.

- **Код и структура:** имена переменных, функций, классов, ключи массивов и объектов,
  CSS-селекторы, имена классов и id, значения `enum`, слаги, константы.
- **Ссылки и пути:** URL, e-mail, `tel:`, `mailto:`, пути к файлам, имена файлов,
  расширения, якоря, query-строки.
- **HTML-теги и атрибуты.** Внутрь `<...>` не заходить. Текстовые атрибуты
  (`alt`, `title`, `placeholder`, `aria-label`, `content` у `meta`) править только если
  об этом попросили явно.
- **Служебные конструкции:** шорткоды `[...]` и их параметры, HTML-комментарии, разметку
  блоков Gutenberg (`<!-- wp:paragraph -->` и JSON в них), шаблонные метки `{{...}}`,
  `%s`, `%1$d`, `{0}`, регулярные выражения, форматные строки.
- **Непечатаемый и кодовый текст:** содержимое `<pre>`, `<code>`, `<script>`, `<style>`,
  `<textarea>`, `<kbd>`, `<samp>`, ограждённые блоки ```` ``` ```` и `` `код` `` в Markdown.
- **Разметку Markdown:** `-` и `*` в начале строки (маркеры списка), `---` (разделитель
  или граница frontmatter), `|` в таблицах, `>` в цитатах, `#` в заголовках.
- **Строки, по которым идёт сравнение в коде.** `if ( $status === 'В работе - ждём' )`
  править нельзя, не поправив все места сравнения.
- **Строки перевода.** Изменение `msgid` (аргумента `__()`, `_e()`, `_x()`) рвёт связь
  с `.po`/`.mo`. Либо править синхронно с файлами переводов, либо не трогать.
- **Фикстуры и снапшоты тестов** — только вместе с ожидаемыми значениями.
- **Уже правильные знаки.** Правила идемпотентны: повторное применение к обработанному
  тексту не должно ничего менять. Если правка ничего не улучшает — не делать её.

## Режимы вывода

Один и тот же результат записывается тремя способами. Выбор зависит от того, как текст
попадёт на страницу.

| Режим | Запись | Когда |
| --- | --- | --- |
| `entities` | `бизнеса&nbsp;&mdash; за&nbsp;5&nbsp;дней` | HTML-разметка, шаблоны, поля, значение которых выводится без экранирования. Правку видно глазами. |
| `mixed` | `бизнеса&nbsp;— за&nbsp;5&nbsp;дней` | Компромисс: невидимый неразрывный пробел — сущностью, видимые знаки — символами. |
| `chars` | `бизнеса — за 5 дней` | Markdown, простой текст, значения, которые выводятся через `esc_html()` / `htmlspecialchars()`. Неразрывный пробел — символ U+00A0. |

По умолчанию для HTML — `entities`, для Markdown и простого текста — `chars`.
В `chars` неразрывный пробел неотличим от обычного на вид, поэтому каждую его установку
надо назвать в отчёте.

## 1. Спецсимволы и знаки в тексте

Настоящий знак вместо эмуляции (§ 62, п. 16).

| Было | Стало | Условие |
| --- | --- | --- |
| `(C)` `(c)` `(с)` | `©` | и с кириллической «с» |
| `(R)` `(r)` `(р)` | `®` | |
| `(TM)` `(tm)` `(тм)` | `™` | |
| `...` и больше точек | `…` | |
| `+-` `+/-` | `±` | перед числом |
| `2x3` `2х3` | `2×3` | между цифрами, латинская и кириллическая «х» |
| `--` `---` | `—` | |
| `No 5` `N 5` `N° 5` | `№ 5` | перед числом |
| `20 ° C` | `20 °C` | градус прижимается к единице |
| `'` между буквами | `’` | апостроф: `O'Neil` → `O’Neil` |

## 2. Кавычки (§ 62, пп. 03–05; § 104)

- В русском тексте внешние кавычки — **ёлочки** `«…»`, вложенные — **лапки** `„…“`.
- В английском тексте — `“…”`, вложенные `‘…’`.
- Программистские `"…"` не оставлять нигде, кроме кода: они допустимы только в исходниках
  и электронной переписке.
- Уровень вложенности считается по всему фрагменту, в том числе через теги:
  `«<b>текст</b>»` — корректная пара.
- Открывающая или закрывающая кавычка определяется по окружению: после пробела,
  открывающей скобки, тире или начала строки — открывающая, иначе закрывающая.
- Знак дюйма после числа (`15"`) вне кавычек не превращать в кавычку.

```
"Вы все еще верстаете в "Ворде"?"  →  «Вы все еще верстаете в „Ворде“?»
```

Орфографию, «ё» и опечатки не править: типографика — это знаки, а не текст.
Если в тексте есть ошибка, сказать о ней в отчёте отдельно, но не исправлять молча.

## 3. Тире и дефис (§ 62, пп. 06–07; § 97)

- **Тире** `—` — между словами, в прямой речи, в значении «это»: длиннее дефиса в два-три раза.
- **Дефис** `-` — внутри слов: `во-первых`, `из-за`, `бизнес-центр`. Никогда не заменять.
- **Короткое тире** `–` — числовые диапазоны.
- **Минус** `−` — только в математике, если это оговорено.

| Было | Стало |
| --- | --- |
| `Коляныч - за пивом послать!` | `Коляныч&nbsp;— за пивом послать!` |
| `- Первый пункт` (начало строки) | `— Первый пункт` (кроме маркеров списка Markdown) |
| `1990-2000` | `1990–2000` |

Тире всегда прижимается к предыдущему слову неразрывным пробелом и **остаётся на строке
с ним** (§ 62, п. 09), после тире — обычный пробел.

**Диапазоны — только когда это действительно диапазон.** Формальный признак —
с обеих сторон дефиса цифра и рядом нет второго дефиса — отсекает телефоны
(`212-85-06`) и даты ISO (`2020-01-01`), но его недостаточно: `дом 12-14`,
`артикул 15-20`, `1.0-beta` ему тоже удовлетворяют, а диапазоном не являются.
Поэтому решать по смыслу: диапазон — это «от и до» (`1990–2000`, `5–7 дней`,
`с. 12–18`). Плагин здесь ошибается в пользу диапазона — в спорных местах
проверяйте руками.

## 4. Перенос слов и привязки (§ 62, пп. 08–15)

Никто не знает, где браузер разорвёт строку, поэтому обрабатываются все случаи.
На строке не должны оставаться: инициалы, одно-, двух- и часть трёхбуквенных слов, цифры
года. На строке должно остаться длинное тире.

Неразрывный пробел ставится:

| Правило | Пример |
| --- | --- |
| После одно- и двухбуквенных слов | `в&nbsp;лесу`, `и&nbsp;я`, `не&nbsp;знаю` |
| После коротких предлогов и союзов | `без`, `близ`, `вне`, `для`, `из`, `изо`, `как`, `меж`, `над`, `обо`, `ото`, `под`, `при`, `про`, `что`, `чем`, `или`, `либо`, `если`, `пока`, `лишь`, `хотя`, `уже`, `ещё` |
| Перед частицами | `я&nbsp;бы`, `если&nbsp;б`, `он&nbsp;же`, `так&nbsp;ли` — `бы`, `б`, `же`, `ж`, `ли`, `ль` |
| В инициалах | `В.&nbsp;И.&nbsp;Пупкин`, `А.&nbsp;Лебедев` |
| Между числом и следующим словом | `за&nbsp;5&nbsp;рабочих дней`, `5&nbsp;кг`, `12&nbsp;января`, `2024&nbsp;г.` |
| В разрядах числа | `1&nbsp;000&nbsp;000` |
| После знаков `№`, `§` | `№&nbsp;45`, `§&nbsp;62` |
| Перед знаками `%`, `‰`, `°`, `₽`, `€`, `$` | `20&nbsp;%`, `451&nbsp;°F` |
| После `©`, `®`, `™` | `©&nbsp;2000 Vassily Poupkine` |
| В сокращениях | `т.&nbsp;е.`, `и&nbsp;т.&nbsp;д.`, `т.&nbsp;п.`, `г.&nbsp;Москва`, `ул.&nbsp;Ленина` |
| Перед тире | `слово&nbsp;— слово` |

Строгих правил нет, все они рекомендательные (§ 62, п. 12): каждый раз надо вникать
в смысл — предлоги и союзы привязывать к следующему слову, частицы к предыдущему.

### Неразрывные диапазоны

Когда неразрывного пробела недостаточно, используется `<nobr>` (§ 62, пп. 13–15) —
для телефонов и слов через дефис, которые некоторые браузеры рвут по дефису:

```html
<nobr>212-85-06</nobr>   <nobr>во-первых</nobr>
```

Применять только по прямой просьбе и только в HTML: в простом тексте и в Markdown теги
недопустимы. Телефон писать с двумя дефисами (`212-85-06`), не на западный манер
(`212-8506`); подряд идущие номера можно разделять пробелами вместо дефисов (§ 91).

## 5. Пробелы и знаки препинания

- Убрать повторяющиеся пробелы и табуляции внутри строки (не в отступах кода
  и не в блоках, размеченных пробелами).
- Убрать пробелы в конце строк.
- Убрать пробел перед `,` `;` `:` `!` `?` `…` и перед точкой в конце предложения.
- Поставить пробел после `,` и `;`, если следом сразу буква. Не трогать `1,5` и `т.е.`
  (это отдельное правило сокращений).
- Убрать пробелы внутри скобок и кавычек: `( текст )` → `(текст)`, `« текст »` → `«текст»`.

## Справочник знаков (§ 62, п. 02)

| Знак | Сущность | Название |
| --- | --- | --- |
| `§` | `&sect;` | параграф |
| `©` | `&copy;` | охрана авторского права |
| `®` | `&reg;` | зарегистрированный товарный знак |
| `™` | `&trade;` | товарный знак |
| `°` | `&deg;` | градус |
| `«` `»` | `&laquo;` `&raquo;` | кавычки-ёлочки |
| `„` `“` | `&bdquo;` `&ldquo;` | лапки (открывающая, закрывающая) |
| `“` `”` | `&ldquo;` `&rdquo;` | английские лапки |
| `‘` `’` | `&lsquo;` `&rsquo;` | одиночные кавычки, апостроф |
| `•` | `&bull;` | жирная точка |
| `–` | `&ndash;` | короткое тире |
| `—` | `&mdash;` | тире |
| `−` | `&minus;` | минус |
| `±` | `&plusmn;` | плюс-минус |
| `×` | `&times;` | знак умножения |
| `…` | `&hellip;` | многоточие |
| `№` | `&#8470;` | знак номера |
| `U+00A0` | `&nbsp;` | неразрывный пробел (невидим, но занимает место) |

## Эталонный пример (§ 62, п. 18)

Сырой текст:

```
...Когда В. И. Пупкин увидел в газете ("Сермяжная правда" N 45) рубрику
Weather Forecast(R), он не поверил своим глазам - температуру обещали +-451 °F.
```

Результат в режиме `chars`:

```
…Когда В. И. Пупкин увидел в газете («Сермяжная правда» № 45) рубрику
Weather Forecast®, он не поверил своим глазам — температуру обещали ±451 °F.
```

Тот же результат в режиме `entities`:

```
&hellip;Когда В.&nbsp;И.&nbsp;Пупкин увидел в&nbsp;газете (&laquo;Сермяжная правда&raquo;
&#8470;&nbsp;45) рубрику Weather Forecast&reg;, он&nbsp;не&nbsp;поверил своим глазам&nbsp;&mdash;
температуру обещали &plusmn;451&nbsp;&deg;F.
```

## Чек-лист перед сдачей работы

- [ ] Не осталось программистских кавычек `"` в человекочитаемом тексте.
- [ ] Нет дефиса между словами там, где нужно тире; дефис внутри слов сохранён.
- [ ] Тире не может оказаться в начале строки — перед ним неразрывный пробел.
- [ ] Телефоны, даты, версии и артикулы не превратились в диапазоны.
- [ ] Ссылки, пути, ключи, атрибуты, шорткоды и код не изменились.
- [ ] Маркеры списков и разделители Markdown на месте.
- [ ] Режим вывода один на весь файл.
- [ ] Повторный проход по результату ничего не меняет.
- [ ] Каждая правка названа в отчёте, включая невидимые неразрывные пробелы.
- [ ] Если правились `msgid` — синхронно поправлены `.po`/`.pot`.
